## Stack and layout

- **Next.js 16.3.5** (App Router) + **React 19.2** + **TypeScript strict** + **Tailwind CSS v4**.
- App code lives under `src/app/` (`layout.tsx`, `page.tsx`, `globals.css`). Import alias `@/*` → `./src/*`.
- Tailwind v4 has no `tailwind.config`: theme tokens are declared in CSS via
  `@import "tailwindcss"` + `@theme inline` in `src/app/globals.css`, and the only
  PostCSS plugin is `@tailwindcss/postcss`. Add design tokens there, not in a JS config.
- Fonts are wired as CSS variables (`--font-geist-sans`, `--font-geist-mono`) in
  `layout.tsx` and mapped to `--font-sans` / `--font-mono` in `globals.css`.
- App routes: `login/`, `auth/confirm/`, `(app)/dashboard/` (twins, train, generate,
  characters) and webhooks under `api/`. Server logic lives in `src/lib/` (Supabase
  clients in `src/lib/supabase/`, providers `fal.ts` / `replicate.ts`, video assembly
  in `video-pipeline.ts`). Session refresh runs in `src/proxy.ts`.

### Next.js 16 specifics that differ from older versions

`AGENTS.md` (regenerated by `next dev`, so keep it committed) is the authoritative
warning: check `node_modules/next/dist/docs/` before writing App Router code.
Concretely, already visible in this repo: layout/page props use the generated global
helper types (`LayoutProps<"/">`, and `PageProps<...>` for pages) rather than a
hand-written `{ children }: { children: React.ReactNode }` — these come from
`.next/types`, so run `next dev`/`next build` once after adding a route or the types
will not resolve.

## Infra and external services

Supabase and Vercel are reachable through the MCP servers declared in `.mcp.json`
(Supabase is pinned to project ref `drcauxnifvcuzdekjgaw`; both are enabled in
`.claude/settings.local.json`). Prefer those tools for inspecting the database,
applying migrations, and reading deployment/runtime logs over guessing at schema or
deploy state. If they are unauthenticated, tell the user to run `/mcp`.

Environment: `.env.local` is gitignored (`.env*`) and holds the public Supabase URL
and anon key. Server-side secrets are pulled with `vercel env pull .env.local` once
the Vercel project is linked. Schema lives in `supabase/migrations/`; every migration
applied through MCP must also be saved there. Verify the live schema via MCP before
writing queries, and regenerate `src/lib/supabase/database.types.ts` after changes.
